**Goal:** An Edge extension that saves a private, local copy of every Google Form you submit: which
form, when, and your answers. You can search those copies, open them, delete them and export them.

**Architecture:** Manifest V3, with no build step and no dependencies at runtime. A content script on
Google Forms pages reads the questions from the page, captures your answers when you submit, and
saves the record to `chrome.storage.local` only after Google's confirmation page loads. A single
extension page (`history.html`) is both the toolbar popup and a full-tab history view. There is no
service worker, no server and no network access.

**Tech Stack:** Plain JavaScript (ES2022), HTML and CSS. `node:test` for unit tests (Node 22+, built
in). Playwright for one end-to-end test (D3). The target browser is Microsoft Edge (Chromium); it
runs unchanged in Chrome.

**Spec:** the Spec section below. It's kept in this file so the plan and the spec can't drift apart.

## Spec

### Problem
Google Forms doesn't give you a copy of what you submitted, unless the form owner turned on response
receipts. Once you've sent a form, you can't see your answers again.

### Users
One person, the owner, on their own Windows PC in Edge. No accounts and no sharing.

### Must do (v1)
1. **Capture on submit.** When a Google Form is submitted and Google shows its confirmation page,
   save one record: form title, form ID, form URL, submitted-at time (ISO 8601), and every
   question paired with your answer.
2. **Save nothing if the submit fails.** If Google rejects the submit (for example, a required
   question is missing), nothing is saved.
3. **Multi-page forms.** Answers from every page end up in the one record.
4. **All standard question types:** short answer, paragraph, multiple choice (including "Other"),
   checkboxes (several values), dropdown, linear scale, rating, multiple-choice grid, checkbox
   grid, date, time. File upload saves the file name only, never the file.
5. **History view:** newest first, with a search box over form title, question text and answers.
   Click a record to see all its questions and answers.
6. **Delete:** delete one record, or delete all (asks for confirmation first).
7. **Export:** download all records as JSON (full fidelity) and as CSV (one row per answer).
8. **Local only.** No network requests, ever. Data lives in `chrome.storage.local` on this PC.

### Won't do (v1)
Sync across devices, cloud backup, auto-filling forms, editing saved answers, forms on sites other
than Google Forms, publishing to the Edge or Chrome store, and building forms (owner-side) features.

### Success criteria
- Submitting a real multi-page test form with every question type produces exactly one record whose
  answers match what you typed, in question order.
- A submit blocked by a missing required answer produces no record.
- With DevTools open on the network panel, the extension makes zero requests of its own.

## Global Constraints

- `manifest_version: 3`. No Manifest V2 APIs (see `.claude/skills/chrome-extensions`).
- Permissions: exactly `["storage"]`. No `tabs`, no `activeTab`, no `<all_urls>`.
- Content script matches: exactly `https://docs.google.com/forms/*`, with `all_frames: true` so forms
  embedded on other sites in a Google iframe are captured too.
- No `fetch`, `XMLHttpRequest`, `WebSocket` or `sendBeacon` anywhere in `extension/`.
- No `innerHTML`, `insertAdjacentHTML`, `eval` or `new Function` anywhere. Form text is untrusted, so
  render it with `textContent`.
- No inline `<script>` and no inline event handlers in HTML.
- No runtime dependencies. Dev-only dependency: `@playwright/test` (if D3 is yes).
- Storage key names: `records` (array) and `pending` (object keyed by form ID). Nothing else.
- Record schema (exact):
  ```js
  {
    id: string,            // crypto.randomUUID()
    formId: string,        // the ID in /forms/d/e/<ID>/ or /forms/d/<ID>/
    formTitle: string,
    formUrl: string,       // the viewform URL, with no query string
    submittedAt: string,   // new Date().toISOString(), set on the confirmation page
    answers: Array<{ question: string, answer: string | string[] }>
  }
  ```

## Review Focus

These are the failure modes most likely to bite a real user that the Spec doesn't spell out. Each one
has a test in the task that owns it.

1. **Submit blocked by validation:** a pending record is created but no confirmation follows.
   Expected: no saved record, and the pending entry is replaced on the next attempt. Tested in Task 4.
2. **Multi-page form, Back then Next:** answers changed on an earlier page. Expected: the final values
   win and no question appears twice. Tested in Task 5.
3. **The same form submitted twice:** expected two separate records, both kept. Tested in Task 4.
4. **A CSV answer starting with `=`, `+`, `-` or `@`:** Excel would treat it as a formula. Expected: the
   cell is prefixed with `'`. Tested in Task 7.
5. **A question title containing HTML such as `<img onerror>`:** expected to show as literal text, never
   run. Tested in Task 6.

## File Structure

```
extension/
  manifest.json      MV3 manifest. Sets the popup to history.html and the content script.
  record.js          Pure functions: parsing the form's question map and building a record. No DOM, no chrome.*.
  content.js         Runs on Google Forms pages: reads questions, captures on submit, confirms on the response page.
  history.html       Popup and full-tab history page (same file).
  history.js         Lists, searches, views, deletes and exports records.
  history.css        Styles for history.html.
tests/
  record.test.js     node:test unit tests for record.js.
  csv.test.js        node:test unit tests for the CSV export.
  e2e.spec.js        Playwright: loads the unpacked extension and submits a routed fixture form.
  fixtures/          Saved Google Form HTML pages from Task 1.
README.md            Install, use, test and privacy notes.
package.json         Test scripts only. No runtime dependencies.
```

`record.js` ends with `if (typeof module !== 'undefined') module.exports = { ... }`, so the same file
loads as a content script and under `node:test` with no build step.

### Task 2: `record.js` — build a record from form data

**Files:**
- Create: `extension/record.js`
- Test: `tests/record.test.js`

**Interfaces:**
- Produces:
  - `parseQuestions(paramsJsonList: string[]) -> Array<{ entryId: string, title: string, rows?: Array<{ entryId: string, label: string }> }>`
  - `buildAnswers(questions, pairs: Array<[string, string]>) -> Array<{ question: string, answer: string | string[] }>`
  - `formIdFromUrl(url: string) -> string | null`

- [ ] **Step 1: Write the failing tests** in `tests/record.test.js`, using `node:test` and `node:assert/strict`:
  - `formIdFromUrl('https://docs.google.com/forms/d/e/1FAIpQLSabc/viewform?usp=sf_link')` returns `'1FAIpQLSabc'`
  - `formIdFromUrl('https://example.com/')` returns `null`
  - checkboxes: pairs `[['entry.1','A'],['entry.1','C']]` give `answer: ['A','C']`
  - "Other": pairs `[['entry.2','__other_option__'],['entry.2.other_option_response','Blue']]` give `answer: 'Other: Blue'`
  - date: `entry.3_year=2026`, `_month=10`, `_day=5` give `answer: '2026-10-05'`
  - time: `entry.4_hour=09`, `_minute=30` give `answer: '09:30'`
  - grid: each row becomes its own answer, `question: 'Title / Row label'`
  - unanswered optional question: left out of `answers`
  - answers come out in question order, not form-data order
  - an unknown `entry.N` with no matching question is kept with `question: 'entry.N'`, so no answer is ever lost
- [ ] **Step 2: Run to see them fail.** `node --test tests/` fails with `Cannot find module '../extension/record.js'`.
- [ ] **Step 3: Implement** the three functions in `extension/record.js` to the signatures above, using the
  field names confirmed in Task 1's `NOTES.md`.
- [ ] **Step 4: Run to see them pass.** `node --test tests/` shows every test passing.

### Task 4: Capture on submit, save on confirmation

**Files:**
- Modify: `extension/content.js`
- Test: `tests/e2e.spec.js` (first two cases)

**Interfaces:**
- Consumes: `parseQuestions`, `buildAnswers` and `formIdFromUrl` from Task 2.
- Produces: storage writes to `pending[formId]` and `records` (schema in Global Constraints).

- [ ] **Step 1: Write the failing e2e tests.** Playwright launches Chromium with
  `--load-extension=extension/` through `launchPersistentContext`. `page.route('https://docs.google.com/forms/**')`
  serves the Task 1 fixtures, and the form POST to `/formResponse` is answered with `confirmation.html`.
  - `submits a single-page form and saves one record`: after submitting, `records` has length 1, its
    `answers` match the values typed, and `pending` is empty.
  - `does not save when the submit is rejected`: the route answers the POST with the form page again
    (validation failure). `records` stays empty.
  - `keeps both records when the same form is sent twice`: `records` has length 2.
- [ ] **Step 2: Run to see them fail.** `npx playwright test` fails on `records` length 0.
- [ ] **Step 3: Implement in `content.js`:**
  - On a form page: listen for `submit` on the `<form>` in the capture phase. Build
    `{ formId, formTitle, formUrl, answers }` with `new FormData(form)` and Task 2's functions. Write it
    to `pending[formId]`, replacing any older pending entry.
  - On the confirmation page (as identified in Task 1): read `pending[formId]`, add `id` and
    `submittedAt`, append it to `records`, and delete `pending[formId]`.
  - Read and write with `await chrome.storage.local.get/set`. Wrap every storage call in try/catch and
    log failures with `console.warn('gform-log:', err)`; never throw into the page.
- [ ] **Step 4: Run to see them pass.** `npx playwright test` passes all three cases.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Google changes the Forms page | Capture stops silently | The fixture-based tests pin today's structure; the README says to re-run Task 1 if capture stops |
| Assumed field names are wrong | Tasks 2, 4 and 5 rework | Task 1 verifies them before any code depends on them |
| Forms that need sign-in, with file upload | File names only | Stated in the Spec and the README |
| Edge loads unpacked extensions only in Developer mode | A banner on every start | Acceptable for personal use; publishing is out of scope |
| Records hold personal answers | Anyone with access to this PC's Edge profile can read them | Stated in the README; delete and delete-all are provided |
